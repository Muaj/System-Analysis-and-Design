CS 255 – DriverPass Project Reflection

The DriverPass project involved designing a system for a company that wanted to help students prepare for their DMV driving tests. The client needed a web-based system where customers could schedule driving lessons, take practice tests, access training materials, and manage their accounts. The system also needed to allow employees to manage appointments, track customer progress, and maintain security.

I think I did particularly well at identifying the client's requirements and translating them into a system design. Creating the UML diagrams helped me better understand how different users would interact with the system and how information would move between its components.

If I could revise one part of my work, I would improve my UML diagrams by adding more detail to the different processes, especially how the system handles errors or unavailable appointments. This would make the diagrams more accurate and easier for developers to follow.

I interpreted the user's needs by reviewing the DriverPass interview transcript and identifying the main features the client wanted. I then used those requirements to plan the system's functionality and design. Considering the user's needs is important because a system can work perfectly from a technical standpoint but still fail if it doesn't solve the customer's actual problems.

When designing software, I like to start by understanding the problem and breaking it down into smaller parts. From there, I identify the requirements, plan how different components will interact, and create diagrams to visualize the system. In the future, I would continue using UML diagrams, user feedback, and testing throughout development to make sure the final product meets the client's expectations.
